GitHub events data pipeline

planned

A pipeline that loads public GitHub activity data into PostgreSQL every hour, so it can be queried with SQL.

Problem
GH Archive publishes one large JSON file of public GitHub events per hour. The raw files are too big and too messy to query directly.
How it works
GH Archive hourly file→ raw copy in S3→ validate + flatten→ PostgreSQL→ SQL reports
What it has to handle
  • Running the same hour twice must not create duplicate rows.
  • Bad records are counted and logged. They do not stop the run.
  • A failed download is retried.
Stack
Python, SQL, PostgreSQL, AWS S3

Document Q&A with retrieval (RAG)

planned

Ask a question about a set of documents. The system finds the matching parts and answers from them, with the source shown.

Problem
A language model alone does not know what is inside your own documents.
How it works
documents→ split into chunks→ embeddings→ top matches by cosine similarity→ answer + sources
How it will be measured
A fixed set of test questions. For each one: was the right chunk found, and was the answer correct.
Stack
Python, PyTorch, FastAPI, an LLM API

Guardrail for RAG answers

planned

A check that runs after the RAG system writes an answer. It tests whether the retrieved documents support the answer before the user sees it.

Problem
A RAG system can return an answer that its own documents do not support, and nothing flags it.
How it works
documents + answer→ NLI model score→ conformal threshold→ pass / flag
Why conformal prediction
The cutoff is set from a calibration set, so the error rate is controlled. It is not a hand-picked number.
Stack
Python, PyTorch, cross-encoder NLI model
